## Loading Strategies ✅

### Full Load

Definition:

```text
Load entire table
```

Used:

* Initial pipeline run
* Historical backfills

---

### Incremental Load

Definition:

```text
Load only new/changed records
```

Used:

* Daily production runs
* Reduced compute cost
* Faster pipelines

## Watermarking ✅

You learned:

### Bad choices

```text
id
created_at
```

for mutable tables.

---

### Good choice

```text

```

because it captures:

## Table Behavior Analysis ✅

### Mutable Tables

Rows can change.

Examples:

```text
users_user
books_book
books_category
orders_order
orders_payment
```

Use:

```text
updated_at
```

---

### Append-Only Tables

Rows are usually inserted once.

Examples:

```text
users_userevent
orders_orderitem
```

Use:

```text
timestamp
created_at
id
```

depending on design.

    | Step | Layer           | Component         | What happens                     | Output                                  |
| ---- | --------------- | ----------------- | -------------------------------- | --------------------------------------- |
| 1    | OLTP Source     | Django/Postgres   | App generates transactional data | users, books, orders tables             |

| 6    | Raw Layer       | LocalLoader       | Writes extracted data as file    | raw JSON file                           |
| 7    | Warehouse Ready | Snowflake input   | Raw files ready for ingestion    | S3-like dataset (future Snowflake load) |
