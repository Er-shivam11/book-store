# 10. What is a DAG?

DAG

Directed Acyclic Graph

Breakdown

Directed

Tasks have direction.

```
A

↓

B

↓

C
```

---

Acyclic

No loops allowed.

Invalid

```
A

↓

B

↓

C

↓

A
```

Airflow rejects cycles because task dependencies must always move forward.

---

Graph

Every task is connected.

---

Your DAG

```
Extract

↓

Load Snowflake

↓

dbt Run

↓

Snapshot

↓

Test
```

---

Interview Answer

A DAG defines the workflow of a pipeline by specifying tasks and their dependencies. Airflow executes tasks according to this graph while ensuring there are no cyclic dependencies.

# 14. Scheduler

Scheduler is the **brain** of Airflow.

Responsibilities:

* Reads DAG files
* Determines when a DAG should run
* Creates DAG Runs
* Creates Task Instances

> The Scheduler decides *when* tasks should run, not *how* they run.

# 4. retries


## Why retries matter

Suppose Snowflake is temporarily unavailable.

Without retries

```text
Task fails

Pipeline fails
```

With retries

```text
Task fails

↓

Wait

↓

Retry

↓

Snowflake becomes available

↓

Pipeline succeeds
```

Retries make pipelines resilient.

# 5. retry_delay

```python
retry_delay=timedelta(minutes=2)
```

Airflow waits two minutes before retrying.

Without delay

```text
Fail

Retry immediately

Fail

Retry immediately

Fail
```

This often makes things worse.

With delay

```text
Fail

↓

Wait 2 minutes

↓

Retry
```

The external system has time to recover.

---

Interview Question

Why not retry immediately?

Answer

Because most failures are temporary. Waiting reduces unnecessary load and increases the chance of success.

# 20. Airflow Best Practices

✔ Keep DAGs lightweight (don't do heavy work during DAG parsing).

✔ One task = one responsibility.

✔ Make tasks idempotent.

✔ Don't store large data in XCom.

✔ Use Airflow Connections for credentials.

✔ Avoid `datetime.now()` in `start_date`.

✔ Keep dependencies explicit.

✔ Use retries wisely.

✔ Monitor failures.

✔ Document every DAG.

✔ Separate Dev/Test/Prod environments.

✔ Use Git for version control.

✔ Prefer incremental processing over full reloads.

# 21. Advanced Interview Questions

### Q1. Difference between DAG and Workflow?

A DAG is the Airflow representation of a workflow.

---

### Q2. Difference between Dynamic DAG and Dynamic Task Mapping?

Dynamic DAG → creates DAGs dynamically.

Dynamic Task Mapping → creates tasks dynamically inside a DAG.

---

### Q3. Why use BranchPythonOperator?

To execute different paths based on runtime conditions.

---

### Q4. Why use TriggerDagRunOperator?

To chain independent DAGs while keeping them modular.

---

### Q5. What is ExternalTaskSensor?

A sensor that waits for a task or DAG in another workflow to complete.

---

### Q6. What is an SLA?

A time-based expectation for task or DAG completion. Missing an SLA triggers alerts but does not necessarily fail the task.

---

### Q7. Why avoid large XComs?

Because XCom data is stored in the Metadata Database, which can become slow and bloated.

---

### Q8. Difference between Catchup and Backfill?

Catchup automatically schedules missed runs (when enabled).

Backfill manually runs historical dates.

---

### Q9. What makes a task idempotent?

Running it multiple times produces the same final result without creating duplicates or inconsistencies.

---

### Q10. How would you scale Airflow?

* CeleryExecutor
* KubernetesExecutor
* More workers
* Better task parallelism
* Proper Pools and Queues
* Deferrable Operators
* Optimized DAG design
